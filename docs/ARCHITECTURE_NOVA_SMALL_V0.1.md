# AstraCore Nova Small v0.1 — Architecture Proposal

Status: design specification; not implemented or trained yet.
Repository: https://github.com/cyberworlduniversity/AstraCoreNova

## Goal
Build an independently implemented, small experimental text model whose training and evaluation can be reproduced. This specification is a measurable engineering target, not a claim of novelty or capability.

## Design constraints
- Python 3.10+ for the first reference implementation.
- Keep the existing Nova Field Dynamics prototype isolated as a baseline.
- No pretrained weights, copied AstraCore implementation, or third-party model framework in the clean-room core.
- Standard-library-only prototype first; an optional NumPy acceleration layer may be considered later and must be clearly separated.
- No external API required for local inference.
- Use an explicit UTF-8 byte representation (256 symbols) for the first tokenizer-free baseline. This is simple and multilingual-safe at the byte level, but may be less efficient than a trained tokenizer.
- Record licenses and provenance for every dataset source.

## Proposed model: Nova Field Recurrent Language Model (NFRLM)

### Target configuration (initial, subject to measurement)
- Vocabulary: 256 byte values
- Context window: 256 bytes for v0.1
- Embedding width: 256
- Field-state width: 320
- 4 recurrent field blocks
- 2x expansion in each block's feed-forward component
- Learned initial state and residual gates
- Byte-level next-symbol prediction head
- Parameter target: approximately 3–5 million, depending on exact block matrices; implementation must report the exact count.

### Data flow
1. UTF-8 encode text to byte IDs.
2. Embed byte IDs.
3. Add position/phase signal.
4. Process sequence through stacked recurrent field blocks. Each block updates a bounded field state using input, previous state, learned gates, and nonlinear coupling.
5. Apply normalization and a prediction head.
6. Predict the next byte at every position.
7. Decode generated bytes as UTF-8, using a documented error policy for incomplete sequences.

### Field block (research hypothesis)
A block should expose a testable update: input projection; state projection; gate computation; bounded nonlinear state update; residual connection; feed-forward transform.
The term field dynamics alone is not evidence of a new architecture. Comparisons against simple recurrent baselines are required.

## Required modules
- nova/config.py: validated configuration and defaults
- nova/encoding.py: UTF-8 byte encode/decode
- nova/field.py: field update and recurrent block
- nova/model.py: model forward pass and logits
- nova/loss.py: next-byte cross-entropy
- nova/optimizer.py: first reference optimizer
- nova/train.py: deterministic training loop
- nova/checkpoint.py: versioned save/load with hashes
- nova/generate.py: sampling and stopping
- nova/evaluate.py: held-out loss, perplexity, sample generation
- tests/: numerical, shape, determinism, checkpoint, training, and generation tests

## Milestones and acceptance gates
### M0 — Architecture and tests
- Freeze equations and configuration.
- Write tests for shapes, finite values, deterministic behavior, and parameter counting.

### M1 — Executable model
- Implement forward pass and byte-level output.
- Verify logits shape, loss calculation, and model parameter count.
- Confirm a tiny batch can overfit as a sanity test.

### M2 — Training infrastructure
- Implement dataset streaming, contiguous train/validation/test split, batching, optimizer, gradient clipping, checkpoint/resume, and training logs.
- No test-set leakage.

### M3 — Dataset
- Start with a small licensed, deduplicated dataset.
- Initial experiment target: 5–20 million training bytes/tokens, then scale based on measured learning curves. This is an experiment target, not a guarantee of quality.

### M4 — Training and evaluation
- Train only after baseline tests pass.
- Report train/validation loss, byte-level perplexity, throughput, memory, checkpoints, and samples.
- Compare with a simple baseline using the same data and compute.

### M5 — Hugging Face publication
- Upload model code, configuration, encoding description, dataset card, training logs, checkpoint, evaluation report, and model card.
- Do not publish weights until reproducibility and licensing checks pass.

## Safety and integrity
- Dataset manifests include source URL, license, retrieval date, checksum, and filtering notes.
- Never include credentials, personal data, malware payloads, or private material in training corpora.
- Checkpoint metadata includes architecture version, config hash, dataset manifest hash, code commit, seed, optimizer state, and step.
- Claims about quality, novelty, and capability must be supported by measured results.

## Current status
Only the original deterministic field encoder and associative-memory prototype are confirmed to exist. The model described here is proposed architecture and has not yet been implemented, trained, or evaluated.
